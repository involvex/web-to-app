# 流媒体画中画

自动检测视频播放 — 包括 HLS、DASH、YouTube 嵌入以及普通 MP4 — 并自动进入画中画模式,这样用户在跳转时音视频依然会播放。
当自动进入关闭或漏掉某个流时,可通过工具栏面板逐个控制检测到的视频。

这是一个**内置插件**(`builtin-streaming-pip`),而非单个 `WebViewConfig`
开关:从页面工具栏打开即可,无需网络访问。

::: tip 已就地记录
[特殊设置](/zh/guide/app-actions/edit-common-config/special-settings) 页的“媒体与内容”
section 已提及此功能;本页是其展开。
:::

## 工作原理

1. **检测** — 插件监听 `<video>` 元素(包括页面稍后添加或 SPA 跳转后出现的)。
   来源类型按 URL/后缀分类:
   - `.m3u8` → HLS
   - `.mpd` → DASH
   - `youtube.com` / `youtu.be` → YouTube(iframe/API 支持)
   - 其它 `.mp4`/`.webm` → 普通视频
2. **自动进入**(默认开启) — 当一个符合条件的来源开始播放时,插件先尝试 HTML5
   `requestPictureInPicture()`,必要时回退到 `NativeBridge.enterPiP()`。
   生成应用的目标是 API 28(低 targetSdk),在清单中声明 `PICTURE_IN_PICTURE`
   功能;无运行时权限提示。自动进入的选择按站点持久保存。
3. **面板** — 工具栏面板列出每个检测到的视频及其流类型和开关,另有全局
   **全部进入画中画** / **全部退出画中画** 按钮和 **自动画中画** 开关。

## 画中画面板

面板显示:

- 每个播放器的流类型(HLS / DASH / YouTube / MP4)与视频标题
- 切换该播放器画中画开/关的按钮
- 全局 **全部进入画中画** / **全部退出画中画** 按钮
- **自动画中画** 开关(持久保存,对该站点后续播放生效)

当两个及以上播放器符合条件时,一次仅有一个处于画中画。

## 注意事项

- 画中画是系统级模式;生成应用以 API 28 为目标并在清单中声明 `PICTURE_IN_PICTURE`
  功能。不会弹出额外的权限提示。
- YouTube 检测依赖 iframe 嵌入界面。若站点把播放器包在跨域 iframe 中,
  插件无法触达时,自动进入会回退到手动开关。
- 对于非 YouTube、非 HLS/DASH 的来源(普通 `.mp4`),检测基于 `<video>` 元素,可靠性高。
- 若某页面无法自动进入画中画,请在面板中关闭 **自动画中画** 并使用逐视频开关。
